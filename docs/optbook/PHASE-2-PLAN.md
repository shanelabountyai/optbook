## Ground rules for this phase

- `src/lib/consent/**` stays pure. One additive change is planned, in its own commit before any service code (work item 2.4, D-075): two optional fields on the import plan's rows. No existing field, rule or expected value changes, and `test:consent` and `consent:eval` must print the same totals before and after. Any other change there is a bug fix in its own commit with a regression test under `tests/consent/` and a `D-` row; never to make a database test pass.
- `fixtures/**` is not edited. `git diff --exit-code origin/main -- fixtures/` must print nothing at the end of the phase.
- All Phase 2 code lives in `src/lib/optbook/` and all Phase 2 tests in `tests/optbook/` (D-055). Nothing in `src/lib/optbook/` is imported by `src/lib/consent/`.
- Every service takes the org context and the time as arguments: `(ctx: { orgId: string }, args, at: string)`. `at` is a timestamp string in the engine's format. Only `src/lib/optbook/clock.ts` reads `@/core/clock` (D-059). No service calls `Date.now()`.
- Every query on an optbook table runs inside `withOrg(ctx, ...)` from `@/core/db/rls` **and** filters by `orgId` explicitly: with RLS off, which is how this repository's CI runs, `withOrg` is a plain transaction and scopes nothing. No `asSystem`, no import of `@/core/db/system` outside tests. Only `src/lib/optbook/orgs.ts` imports the plain `db` client, and only to list org ids for the cron jobs (D-057).
- Errors a caller can cause are returned as values: a code from the PRD where one exists, otherwise one of the service codes listed under "Service contracts" (D-076). These are not decision reasons and never appear in a `Decision`. A throw means a bug or a refused database write.
- **`recorded_at` is set by the service, never by the caller** (D-074): `appendDrafts` stamps every draft with the time the ledger learns of it. `occurred_at` is the caller's.
- Services do no authentication or authorisation. They trust `ctx` and their arguments; the routes that call them in Phase 3 are where a session, a role or a token is checked.
- No import from `@/modules/*`, `@/core/email` or any provider SDK anywhere under `src/lib/optbook/` (D-006, D-065). `mocks:lint` enforces it.
- Write the failing test first. Database tests cannot run in the cloud session if Postgres or the Prisma engines are unavailable (D-041): write them anyway, record the exact command and error, and let CI decide. Do not work around a network refusal.
- Template-owned paths are not edited, with one exception the template itself provides: back-relation lines on `Org` in `prisma/schema/core.prisma`, each ending `// app` (D-056). `npm run foundation:drift` must stay clean.

## Schema (named here; written in work item 2.2)

One clone-owned file, `prisma/schema/optbook.prisma`. Every model has `id` (uuid), `orgId` (uuid, required, relation to `Org` with `onDelete: Cascade`) and an index that starts with `orgId`. Decision-relevant times are **text** in the engine's format with a `CHECK` on the pattern (D-059); bookkeeping columns (`createdAt`) are `timestamptz` and are never read by a decision.

| Model | Columns beyond `id`, `orgId` | Constraints and notes |
|---|---|---|
| `Contact` | `displayName?`, `createdAt` | No state, status or subscription column, ever (L-3). Deleted at erasure completion. |
| `ContactIdentifier` | `contactId` (FK to `Contact`, cascade), `channel`, `value` (normalized) | Unique `(orgId, channel, value)` and `(contactId, channel)`. The only columns in optbook's own tables that hold an address or number, with `ImportBatch.fileText` and `ErasureTask.payload` while they are filled. |
| `ConsentEvent` | `eventId` (text), `contactId` (uuid, **no FK**: events outlive the contact row; the same holds for every `contactId` below except `ContactIdentifier`'s), `type`, `channel?`, `purpose?`, `occurredAt`, `recordedAt`, `source`, `method`, `evidenceRef?`, `actorKind`, `actorId?`, `verifiedChannel?`, `kind?`, `choice?`, `fact?`, `value?` (JSON: a string or an integer) | Unique `(orgId, eventId)`; index `(orgId, contactId)`. `CHECK occurredAt <= recordedAt`. Append-only by trigger (D-061). `contactId` is required here (D-042). |
| `DecisionRecord` | `contactId`, `at`, `inputs` (JSON: `at`, message, `recent_sends`, `tombstone_match`), `fingerprint`, `outcome`, `reasons` (JSON), `ruleSetId?`, `ruleSetVersion?`, `basis` (JSON) | The fields of `ProofRecord` in `audit.ts`. Append-only by the same trigger (D-061). |
| `SendLog` | `contactId`, `channel`, `purpose`, `sentAt`, `decisionId?` (FK to `DecisionRecord`, cascade), `messageId?`, `adapter` | Written only by the mock adapters, which always set `decisionId`; it is nullable only so tests can store a golden case's sends without inventing decisions (D-064). Append-only by the same trigger. |
| `EvidenceSnapshot` | `contactId`, `evidenceRef`, `body` (JSON) | Unique `(orgId, evidenceRef)`. Deleted at erasure completion (Q-7). |
| `ErasureRequest` | `contactId`, `requestedAt`, `dueAt`, `ruleSetId`, `ruleSetVersion`, `completedAt?` | Request status is computed by `requestStatus`, never stored. `completedAt` records that the completion step ran. |
| `ErasureTask` | `requestId` (FK, cascade), `system`, `state`, `attempts`, `requeues`, `lastAttemptAt?`, `nextAttemptAt?`, `ackedAt?`, `payload?` (JSON) | Unique `(requestId, system)`. This table is the outbox (D-065). `payload` is set to null on acknowledgement and at completion. |
| `Tombstone` | `hash`, `channel`, `kid`, `requestId` (FK, cascade), `status` (`active`, `lifted`), `liftedAt?` | Index `(orgId, hash, status)`. Never deleted; the only allowed update is `active` to `lifted` (D-061). |
| `ImportBatch` | `sourceLabel`, `mapping` (JSON), `importTime`, `ledgerFingerprint`, `status` (`previewed`, `committed`, `discarded`, `stale`, `expired`), `fileText?`, `summary` (JSON), `supersededById?`, `createdById`, `createdAt` | `fileText` is the uploaded file. `CHECK (fileText IS NULL OR status = 'previewed')`: every other status has no file (D-066). |
| `ImportRow` | `batchId` (FK, cascade), `rowNumber`, `outcome`, `reason?`, `notes` (text array), `drafts` (JSON), `heldDrafts?` (JSON), `identifierHash?`, `contactId?`, `resolution?`, `resolvedById?`, `resolvedAt?`, `resolutionEvidenceRef?` | Unique `(batchId, rowNumber)`. Holds only what the engine's plan returns, never a clear identifier and never a cell of the file (D-066). `identifierHash` is filled for every row whose identifier normalised, `heldDrafts` for `HOLD_REVIEW` rows (D-075). `contactId` is set at preview when the contact exists and at commit for a contact the commit creates. The four resolution columns are created now and written in Phase 3 (D-067). |

## Service contracts (what the build run must not have to guess)

| Question | Answer |
|---|---|
| Service codes that are not in the PRD (D-076) | `UNKNOWN_CONTACT`, `IDENTIFIER_IN_USE`, `UNKNOWN_BATCH`, `BATCH_NOT_PREVIEWED`, `UNKNOWN_TASK`, `UNKNOWN_DECISION`. From the PRD and reused: `NO_IDENTIFIER`, `BAD_IDENTIFIER`, `ERASED_IDENTIFIER`, `LEDGER_CHANGED`, `UNKNOWN_CHANNEL`, `UNKNOWN_PURPOSE`, every `checkAppend` and `planErasure` code. |
| A contact id with no `Contact` row | `appendDrafts` and `sendMessage` return `UNKNOWN_CONTACT`, unless the contact's ledger holds `ERASURE_COMPLETED`, in which case `appendDrafts` returns `CONTACT_ERASED` and `sendMessage` returns `UNKNOWN_CONTACT`. Neither writes anything. |
| A send on a channel the contact has no identifier for | `NO_IDENTIFIER`; no decision is stored. |
| `recorded_at` | `appendDrafts` sets it: `at`, or one second after the contact's latest stored decision if `at` is not already later (D-074). `occurred_at` later than that is refused by `checkAppend`. |
| `recent_sends` given to `decide` | The contact's `SendLog` rows with `sentAt` within the longest window in the configuration (rule sets and frequency choices) before `at`. A test shows the 35 golden decisions are equal with the full log and with the trimmed one. |
| Finding the contacts a file touches | `previewImport` hashes the org's `ContactIdentifier` values on the file's channels with the tombstone key and matches them to the plan's hashes. No hash is stored on `ContactIdentifier`. |
| Tombstone lookup | One function, `activeTombstoneHashes` / `tombstoneMatch` in `tombstones.ts`, used by `createContact`, `sendMessage` and `previewImport`. It hashes with every `kid` that an active tombstone in the org carries, not only the current one, so changing `keys.json` cannot un-suppress anyone. |
| Preview expiry | Measured from the batch's `importTime`. |
| An inbound `STOP` | Arrives with a number. A number on file gets the opt-out; a number not on file creates a contact holding it and the opt-out, as an import's restrictive row does (PRD §5e rule 8, D-076). |
| The mock's attempt number after a requeue | `requeues * max_attempts + attempts`: the script is indexed by attempts ever made. |
| Row mapping | `fromRow` leaves out an optional key that is null in the database when the engine's type marks it optional, and never sets `undefined` (`canonicalJson` refuses it). |
| Transactions | Each service call is one `withOrg` transaction. Before 2.10, read the Prisma 7 notes in `node_modules/prisma` for the interactive-transaction timeout and set it explicitly for `commitImport` and the worker's per-org pass; do not rely on a remembered default. |
